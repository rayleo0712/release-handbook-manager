# 版本发布与更新手册规则

## 1. 版本号唯一真源规则

- 项目必须维护一个唯一的版本配置文件，当前版本号以该配置文件为唯一真源。
- 版本号格式统一为：`v主版本.次版本.修订号`。
- 禁止以 Git 提交记录、分支名、Tag 名等作为版本号唯一依据。
- 每次进入新的开发迭代或发布周期前，必须先维护版本配置文件中的版本号。
- 当前版本涉及的更新手册、脚本、发布清单、验证记录、更新日志，均必须归属于该版本号。

## 2. 版本材料目录规则

- 版本配置文件路径统一为：`release/version.json`。
- 每个版本的发布材料统一存放于：`release/versions/{版本号}/`。
- 当前版本目录下文件采用单层平铺结构，禁止额外增加多级子目录，避免发布执行时误操作。
- 推荐目录结构如下：

```text
release/
  version.json
  versions/
    v1.0.0/
      01-更新手册.md
      02-db-001-数据库结构变更.sql
      02-db-002-历史数据修复.sql
      03-config-001-菜单权限配置.sql
      03-config-002-角色权限配置.sql
      04-发布检查清单.md
      05-发布后验证记录.md
      06-版本更新日志.md
```

## 3. 更新手册唯一真源规则

- 每个版本必须对应一份唯一的 `01-更新手册.md`，作为该版本发布内容的唯一真源。
- 开发过程中与当前版本相关的变更事项，必须持续登记到该版本更新手册中。
- 禁止仅在聊天记录、口头沟通、临时文档中保存发布关键信息而不回收至更新手册。

## 4. 强制登记范围规则

- 凡是超出纯代码提交范围、需要额外执行、额外配置、额外迁移、额外说明的内容，都必须登记到当前版本更新手册。
- 强制登记范围至少包括：
  - 数据库表结构变更
  - 字段新增、修改、删除
  - 主键、外键、索引、约束调整
  - 存储过程、触发器等数据库对象变更
  - 历史数据修复、回填、迁移
  - 菜单、权限、角色权限等数据库驱动配置
  - 字典、参数、流程、模板等数据库驱动配置
  - 原有配置文件调整
  - 生产环境配置调整
  - 需要人工执行的发布操作
  - 回滚步骤与回滚前置条件
  - 本版本全部功能变更、缺陷修复与兼容处理说明

## 5. 必须脚本化规则

- 凡是本质上可以通过数据库执行完成的变更，必须提供可执行 SQL 脚本，不允许只写文字说明。
- 以下场景必须脚本化：
  - 数据库表结构变更
  - 字段、主键、外键、索引、约束调整
  - 存储过程、触发器等数据库对象变更
  - 历史数据修复、回填、迁移
  - 菜单配置
  - 菜单下权限配置
  - 角色权限分配
  - 其他可通过数据库增删改查直接完成的系统配置
- 菜单、权限、角色权限等虽然可在页面上人工配置，但因其底层属于数据库可执行操作，必须按脚本化处理，不得归类为人工操作。
- 数据库类脚本文件统一使用 `02-db-xxx-说明.sql` 命名。
- 配置类脚本文件统一使用 `03-config-xxx-说明.sql` 命名。
- 脚本文件必须通过文件名前缀体现类型和执行顺序。

## 6. 允许人工操作规则

- 仅以下场景允许保留为人工操作步骤：
  - 修改已有配置文件的内容调整（不含新增配置文件）
  - 生产环境配置类操作
  - 确实无法脚本化的事项
- 凡属于人工操作的事项，必须在版本更新手册中明确写清：
  - 操作入口
  - 操作顺序
  - 操作内容
  - 目标结果
  - 校验方式
- 禁止以“现场处理”“按实际情况调整”等模糊语句替代明确操作步骤。

## 7. 发布执行规则

- 每次版本发布时，必须严格按照该版本更新手册执行。
- 发布执行顺序必须明确区分：
  - 发布前检查
  - 数据库脚本执行
  - 配置脚本执行
  - 应用部署
  - 人工操作执行
  - 发布后验证
  - 回滚处理
- 禁止凭记忆、聊天记录或临时口头说明直接上线。

## 8. 更新日志沉淀规则

- 更新手册不仅用于发布执行，还必须记录当前版本全部变更事项。
- 正式发布时，对内发布说明、对外更新日志、升级说明等内容，必须优先从当前版本更新手册提炼生成。
- 禁止在发布时重新临时回忆和拼凑版本变更内容。

## 9. 发布材料完整性规则

- 每个版本的发布交付必须同时包含：
  - `01-更新手册.md`
  - `02-db-xxx.sql`
  - `03-config-xxx.sql`
  - `04-发布检查清单.md`
  - `05-发布后验证记录.md`
  - `06-版本更新日志.md`
- 如某类脚本不涉及，可在更新手册中明确标记“不涉及”。
- 仅有文档、没有可执行脚本，不视为完整交付。
- 仅有脚本、没有手册说明，不视为完整交付。

## 10. 维护责任规则

- 当前版本的需求开发人员，在涉及上述范围的改动时，必须同步维护更新手册与脚本。
- 版本发布负责人在发版前，必须核对版本号、更新手册、脚本、验证项是否一致。
- 如存在未登记事项，不得视为当前版本发布材料已完成。
