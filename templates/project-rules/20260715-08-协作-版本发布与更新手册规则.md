# 版本发布与更新手册规则

> 只留口径与红线；细节按需读 `R/`=`skills/release-handbook-manager/references/`

1. **版本号唯一真源** = `release/version.json` 的 `version`，格式 `v主.次.修`；禁止以 Git 提交/分支/Tag 为依据
   **红线：版本号必须由人工明确指令触发维护，AI 不得自动生成、自动 bump 或自动升级版本号。**
2. **强制登记**：凡超出纯代码提交、需额外执行/配置/迁移/说明的事项须登记进当前版 `01-更新手册.md`；范围→`R/workflow-维护与登记.md`
3. **完整性7类缺一不可**：01手册/02-db-xxx.sql/03-config-xxx.sql/04检查清单/05验证记录/05-1功能验收用例(非技术版)/06更新日志；**05 与 05-1 双轨配套、不得互相替代**
4. **目录口径**：01–06 单层平铺于 `release/versions/{版本号}/`，历史轮次进 `archive/`，此外不得再嵌子目录；发布执行不得读 `archive/`
5. **行格式**：`release/versions/**` 单行 ≤200 字符、表格逐行展开，超过即不合规须重写
6. **细节指向**：初始化/目录→`R/init-初始化流程.md`；SQL模板/多片段校验/命名/脚本化边界→`R/scripts-sql-规范.md`
   发布顺序/手册章节→`R/templates-01-更新手册.md`+`R/templates-04-检查清单.md`；05/05-1结构与账号迁移→`R/templates-05-验证记录.md`+`R/templates-05-1-功能验收用例.md`
   日志提炼→`R/templates-06-更新日志.md`；红线全文→`R/redlines-一票否决红线汇总.md`
