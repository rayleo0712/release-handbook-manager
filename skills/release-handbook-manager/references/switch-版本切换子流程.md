### 7.2.1 版本切换初始化子流程（一票否决强制：人工改完 version.json 但目录未建的必须走这里，禁止跳过）

> **触发条件严格定义**：§7.2 第 2 步命中「分支 B」—— `release/version.json.version` 对应目录不存在，但 `previousVersion` 对应目录存在。
> **典型用户场景**：用户把 version.json 里 `version` 从 v1.1.0 手动改成 v1.2.0、`previousVersion` 从 v1.0.0 手动改成 v1.1.0，之后重新启用 rhm；这是最高频场景，必须 100% 命中。
> **子流程结束后**：返回 §7.2 第 3 步继续执行，后续所有维护操作都在「新建好的 `release/versions/{currentVer}/` 目录」下进行。

子流程执行顺序（固定 9 步，缺一步即视为失败）：

1. **Step 1：创建当前版本目录并就位批量执行器**
   - 在 `release/versions/` 下创建 `{currentVer}/` 目录，除 `archive/` 外不得再嵌子目录
   - 立即按 `runner-批量执行器.md` §2 从 skill 资产复制（或网络下载）`run-release.ps1` 到新目录；执行器版本无关、零修改；**禁止从上一版复制旧副本，也禁止逐行现场生成**
2. **Step 2：创建 02/03 SQL 类占位文件（不迁移，重新编号开始；登记新变更按 §4.3 归并优先）**
   - 严禁从上一版 `02-db-xxx.sql` / `03-config-xxx.sql` 直接复制文件内容到新版（每个版本脚本必须独立可追溯）
   - 当前目录先保持空，待实际变更出现时从 `001` 开始按 `scripts-sql-规范.md` §4.4 命名文法（三位定宽、同前缀唯一）编号创建；同功能单元变更必须按 §4.3 追加片段归并，不得一条变更建一个文件；跨文件依赖必须写 `-- @depends`；如确实需要占位，仅允许保留号 `000`：`02-db-000-本版暂无数据库脚本.sql` / `03-config-000-本版暂无配置脚本.sql`（runner 自动跳过不执行）
3. **Step 3：迁移 5 份必选文件（01/04/05/05-1/06），按各自的「保留骨架 + 清空已填结果 + 跨版本字段重填」规则处理**
   - 规则总原则：**结构骨架与可复用模板部分（表头、固定章节标题、检查项骨架、05 章节骨架、05-1 用例固定 10 列表头、06 双面结构骨架）完整复制；所有已填的「实际结果/通过不通过/验收人/签字/日期/截图路径/sha256 校验值/P0P1P2 计数字」全部清空置空；版本号、基本信息、上一版本号、变更台账跨版本标记必须按 currentVer/prevVer 重新填充**
4. **Step 3-1：迁移 01-更新手册.md（最关键）**
   - 保留 9 章节固定骨架（§1~§9 严格对齐 §6.1）
   - **必须重写的字段（不得遗漏）**：
     - `§1 基本信息`：版本号 → `currentVer`；上一版本 → `prevVer`；当前状态 → `developing`；一句话说明、版本负责人、计划发布时间按实际/占位
   - **必须全部清空的区域（留白给新版从头填）**：
     - `§3.1 新增功能`：全清空，留模板占位注释"每条 1 行，做了什么+业务价值"
     - `§3.2 新增接口与权限`：全清空，只留 4 列简表头
     - `§3.3 功能调整`：全清空，留模板占位注释
     - `§3.4 缺陷修复`：全清空，留模板占位注释
     - `§3.5 兼容性处理`：全清空，留模板占位注释
     - `§3.6 风险说明`：全清空，只留 4 列简表头
     - `§4.1 数据库脚本`：全清空，只留 4 列简表头（因为 02 脚本全部重建不迁移）
     - `§4.3 配置脚本`：全清空，只留 3 列简表头
     - `§5 必须人工介入的操作点`：全清空，只留 4 列简表头
     - `§6.2 执行顺序`：8 步骨架保留即可，实际行可清空
     - `§7 回滚方案`：全清空，只留 3 列简表头（每版回滚必须独立评估，不得沿用旧版）
   - **跨版本选择性迁移的特殊区域（§3.7 变更台账，必须逐行人工判断）**：
     - 表头行完整保留（10 列固定：变更编号/所属版本/功能域/当前状态/原始需求摘要/当前有效摘要/本轮调整摘要/影响范围/关联用例编号/备注）
     - 上一版台账中，**`当前状态 = released / cancelled / merged`** 的记录：**严禁迁移到新版**，它们属于上一版归档内容，必须永远留在上一版 01 中
     - 上一版台账中，**`当前状态 = draft / developing / adjusting / testing`** 且 业务上明确要"跨版本延续到下一版继续做"的记录：
       1. 先向用户列表列出所有符合条件的候选记录（列出变更编号 + 当前有效摘要 + 当前状态），并问："以下为上一版未发布且可能跨版本延续的变更，请明确指定哪些需要带到新版本"
       2. 等待人工明确回复（可多选/全选/一条不选）后，再把被选中的记录写入新版 §3.7
       3. 写入新版时必须做两处字段更新：`所属版本` → `currentVer`；`当前有效摘要` 行尾标注 `（从上一版 {prevVer} 跨版本延续）`
     - 严禁"AI 自己判断哪些该延续、哪些该不延续"直接替用户选，**必须先列候选再等待人工明确选择**
   - **必须全部清空的签字/结果区**：`§9 三方签字区` 全部签字位/日期/结论清空，只留 8 列简表头
5. **Step 3-2：迁移 04-发布检查清单.md**
   - 75+ 项 Checklist 的「检查项名称 / 检查依据 / 预期结果 / 对应材料文件」骨架完整保留
   - **全部清空**：实际核验结果列、人工签字列、实际日期列、实际 sha256 列、所有"已通过 / 不通过 / N/A"填写位——这些只能在本版真实执行时填，不得沿用旧版
6. **Step 3-3：迁移 05-发布后验证记录.md**
   - 技术验证章节骨架（SQL执行结果 / 代码自检 / 错误码 / 并发 / 缓存 / denorm 回填 / 双写对账 等章节标题）完整保留
   - **全部清空**：实际 SQL 执行结果截图路径、实际通过/失败勾选、实际压测数据、实际命中率、实际错误码、实际回归人、实际日期——不得把旧版的通过记录带过来
7. **Step 3-4：迁移 05-1-功能验收用例(非技术版).md（本步与 §6.3.1 账号迁移规则联动）**
   - `## 1. 验收范围`、`## 3. 用例清单`、`## 4. 测试环境`、`## 5. 缺陷记录`、`## 6. 截图与附件`、`## 7. 回归清单` 章节标题保留，**所有用例行、缺陷行、截图路径、验收人、实际结果、日期、通过不通过全部清空**（每版验收必须独立重写用例）
   - `## 八 验收汇总表`：**P0/P1/P2 计数字（含合计行）必须全部留空**（与 §6.3.1(g) 初始化规则一致，严禁沿用旧版数字）
   - `## 2. 角色准备` 表：**严格按 §6.3.1 账号迁移口径执行 —— 仅从上一版同名 05-1 文件读取 `## 2. 角色准备`，按「角色列名完全匹配」迁移「测试账号」「测试密码」两列；找不到匹配角色时回落模板默认值；严禁追溯更老版本**
8. **Step 3-5：迁移 06-版本更新日志.md**
   - 双面结构骨架（对外业务面 + 对内技术面）完整保留
   - **全部清空**：实际条目内容、版本时间、对外发布文案；等待新版 §3.1~§3.7 填充后再从 01 提炼生成
9. **Step 4：回写确认 —— 子流程结束前必须执行的自检（输出时列给用户核对）**
   - 输出清单：已创建目录 `release/versions/{currentVer}/`、已生成/迁移的文件名列表（逐项列出实际文件名，必须包含 `run-release.ps1`，不得只写份数）、`01 §3.7 变更台账` 候选待人工确认清单（如有）
   - 明确告诉用户："已完成 v{prevVer} → v{currentVer} 版本切换初始化，目录与空白骨架已就绪。如需把上一版未发布的跨版本延续变更带入新版，请在上方候选清单中明确选择，我会写入新版 §3.7。"

### 7.2.2 版本切换触发入口（用户常用话术识别）

除了上述 §7.2 第 2 步自动检测分支 B 外，用户在对话中说出以下任意表述时，**必须优先进入 §7.2.1 版本切换初始化子流程**，不得让用户先手动改 version.json 再等自动检测：

- "把版本升级到 v1.2.0" / "切版本到 v1.2"
- "开始 v1.2.0 版本" / "准备 v1.2 版本目录"
- "把 v1.1 的发布材料迁到 v1.2" / "从上一版复制模板开新版本"
- "版本号已经改好了，帮我生成 1.2 的目录和材料"
- "版本切了但目录还没建"

话术识别触发时，操作顺序：**先按 §2.4 红线写 version.json（仅当用户明确给出版本号时允许写）→ 再立即进入 §7.2.1 完成目录与模板迁移**，两步合成一次执行，不得分步漏做。
