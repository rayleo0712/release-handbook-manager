### 6.2 `04-发布检查清单.md`

职责：

- 在正式发布前核对版本号、脚本、手册、人工操作、回滚方案是否齐全
- 承载 **§8 命令区**：全项目命令的唯一落点（启动命令 / 数据恢复命令 / 四种执行场景命令模板 / 05-1 计数与回填 / 临时命令记录）；
  `01` / `05` / `05-1` / `06` 只写指向 §8 的说明，严禁内联命令本体
- 承载 **§9 发布角色 × 真源文件索引表**：固定 8 行，角色列不得留空，是各角色「该读哪份文件、负责哪些章节」的唯一索引
- 承载 **§10 附件清单**：以 `ATT-04-N` 编号登记本版本全部附件及其指向真源，`ATT-04-1` 必须指向 `05-1`

建议检查项至少包括：

- `release/version.json` 是否已更新
- 版本号格式是否正确
- 当前版本目录是否已创建
- 更新手册是否已补充完整
- 所有数据库变更是否均已生成 `02-db-xxx` 脚本
- 所有配置类数据库操作是否均已生成 `03-config-xxx` 脚本
- 所有人工操作事项是否已明确登记，且均落在 `scripts-sql-规范.md` §4.2 的 8 类范围内
- 发布执行顺序、发布后验证、回滚方案是否已确认
- `05-1` 表头是否为 §(f) 规定的 10 列固定结构（用例编号 / 来源变更编号 / 覆盖类型 / 优先级(P0/P1/P2) /
  页面(中文路径+URL) / 操作(步骤编号123) / 预期(可判定结果) / 实际结果 / 验收人 / 备注）
- §8 命令区各表是否已写出可直接复制执行的命令本体，且模板变量已全部替换为真实值
- §9 索引表 8 行、§10 附件清单是否填写完毕
