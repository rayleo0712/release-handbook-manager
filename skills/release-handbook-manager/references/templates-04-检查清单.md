### 6.2 `04-发布检查清单.md`

职责：

- 在正式发布前核对版本号、脚本、手册、人工操作、回滚方案是否齐全
- 承载 **§8 命令区**：全项目命令的唯一落点（启动命令 / 数据恢复命令 / 四种执行场景命令模板 / `run-release.ps1 -ListOnly` 顺序预检、`-StopOnError` 正式执行与 `-StartIndex/-EndIndex` 失败补跑命令 / 05-1 计数与回填 / 临时命令记录）；
  `01` / `05` / `05-1` / `06` 只写指向 §8 的说明，严禁内联命令本体
- 承载 **§9 发布角色 × 真源文件索引表**：固定 8 行，角色列不得留空，是各角色「该读哪份文件、负责哪些章节」的唯一索引
- 承载 **§10 附件清单**：以 `ATT-04-N` 编号登记本版本全部附件及其指向真源，`ATT-04-1` 必须指向 `05-1`

建议检查项至少包括：

- `release/version.json` 是否已更新
- 版本号格式是否正确
- 当前版本目录是否已创建
- 更新手册是否已补充完整
- 所有数据库变更是否均已生成 `02-db-NNN` 脚本
- 所有配置类数据库操作是否均已生成 `03-config-NNN` 脚本
- 同功能单元变更是否已按 `scripts-sql-规范.md` §4.3 归并到同脚本片段，而非一条变更一个文件
- SQL 文件名是否符合 `scripts-sql-规范.md` §4.4 文法（`前缀-NNN(三位定宽)-简述.sql`、同前缀 NNN 唯一），跨文件依赖是否已写 `-- @depends` 机器声明（不得只写注释）
- 版本目录是否满足 §4.5 单一通道：无黑名单跳过类脚本、无 `@test-only` 测试专用/造数脚本（应在 `scripts/test-auto/`）、无缺校验区脚本、000 占位仅含注释
- 每个脚本执行后是否都有可判定反馈（PASS/FAIL），不存在「执行了但无校验」的脚本
- 是否已执行 `run-release.ps1 -ListOnly` 且 0 违例，执行计划与 `01 §4.1/§4.3` 行序一致
- 版本目录下固定名 `run-release.ps1` 是否已就位（每版本一个，获取方式见 `runner-批量执行器.md`）
- 所有人工操作事项是否已明确登记，且均落在 `scripts-sql-规范.md` §4.2 的 8 类范围内
- 发布执行顺序、发布后验证、回滚方案是否已确认
- `05-1` 表头是否为 §(f) 规定的 10 列固定结构（用例编号 / 来源变更编号 / 覆盖类型 / 优先级(P0/P1/P2) /
  页面(中文路径+URL) / 操作(步骤编号123) / 预期(可判定结果) / 实际结果 / 验收人 / 备注）
- §8 命令区各表是否已写出可直接复制执行的命令本体，且模板变量已全部替换为真实值
- §9 索引表 8 行、§10 附件清单是否填写完毕
