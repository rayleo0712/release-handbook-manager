### 6.3 `05-发布后验证记录.md`（技术版规范保留）

职责：

- 记录正式发布后的执行结果和验证结果（**面向测试/开发人员的技术版验证记录真源**）

建议至少覆盖：

- 数据库脚本执行结果
- 配置脚本执行结果
- 人工操作执行结果
- 核心功能验证结果
- 菜单权限验证结果
- 数据结果验证
- 页面显示验证
- 日志记录验证
- 异常与处理
- 最终结论

## 索引 + 归档结构（强制，P0-1 新口径）

05 是**发布后验证的索引文件**，不是明细堆叠文件。固定四段结构：

| 段 | 内容 | 约束 |
| :-- | :-- | :-- |
| §1 执行信息 | 版本号 / 当前轮次 / 发布时间 / 执行人 / 验证人 / 本轮范围 | 每轮更新 |
| §8 最终结论 | 发布结果 / 是否回滚 / 结论说明 / 三方签字 | 每轮更新 |
| §9 最近一轮验证摘要 | 脚本执行、人工操作、功能验证、异常处理 | **≤40 行**，只保留最近一轮 |
| §10 历史轮次索引 | 表格：轮次 / 日期 / 范围 / 结论 / 归档文件链接 | 每完成一轮追加一行 |

**体积门槛：05 本体 ≤20 KB。** 超过即视为不合规，必须先把历史轮次迁出再看体积。

**历史轮次迁出规则：**

- 每完成一轮验证，把该轮 §9 全文剪切到 `archive/05-验证记录-第N轮.md`
- 在 §10 索引表追加一行，链接指向该归档文件
- 05 本体只保留最近一轮摘要，禁止把历轮明细堆在本文件内

**目录口径：** 发布执行文件（01–06）单层平铺；历史归档统一放 `archive/` 子目录，
发布执行时不得读取 `archive/`。

**为什么必须这样：** 单文件持续追加会让 05 长到几百 KB，任何一次「读 05」都要付全量 token，
且 AI 无法只读最近一轮。索引 + 归档结构使「只读 §9 + §10」成为可能。
