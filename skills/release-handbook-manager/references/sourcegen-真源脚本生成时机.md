# 真源驱动的脚本生成时机（>50 KB 挂起重生成）

> 来源：生成内容臃肿治理新增（2026-10-22）
> 加载时机：从本地真源文件全量生成 02/03 脚本、真源发生变更决定是否重生成、发布准备统一刷新「待刷新」脚本

---

## 1. 适用场景与判定

- **真源驱动脚本**：内容从本地某个真源文件（配置导出 / JSON / 代码扫描等）读取后**全量生成**的 `02-db-NNN` / `03-config-NNN` 脚本（典型：数百行 INSERT 的菜单权限 / 角色授权脚本）
- **只约束「全量重生成」动作**（读真源 → 从头生成整个 SQL 文件）；以下动作不受本节约束：
  - `scripts-sql-规范.md` §4.3 归并追加片段 —— 局部定点编辑，照常执行
  - 头部四字段 / 尾部校验区的补写与修正 —— 定点编辑，照常执行
- **体积口径**：目标脚本 UTF-8 实际字节数 > 50 KB（51200 字节，`Get-Item 文件.Length` 实测；不是行数也不是字符数）
- **≤50 KB 的真源驱动脚本**：不适用挂起，真源变更时随变更同步更新（维持现有行为）

## 2. 挂起规则（>50 KB，`version.json.status = developing` 的日常维护轮）

1. 真源发生变更时，**禁止**自动重新生成整文件；唯一动作 = 把 `01 §4.1/§4.3` 表中该文件的「真源状态」列改为 `待刷新`
2. 挂起期间该脚本仍可按 §4.3 追加片段（局部编辑）；追加的片段须在片段注释中标明来源，供重生成时比对并入
3. **强制刷新只有两个触发点**：
   - 用户明确指令「重新生成 / 刷新 02-db-XXX / 03-config-XXX」→ 立即以最新真源重生成该文件
   - 进入发布准备（巡检模式，`inspect-发布前巡检.md`）→ 统一重生成**全部**「待刷新」脚本
4. **重生成纪律**：
   - 重生成前必须比对挂起期间追加的片段，将未被真源覆盖的片段并入新文件，禁止直接丢弃
   - 重生成完成后「真源状态」改回 `已同步`
   - 重生成产物同样必须满足 §4.1 头部四字段 + 尾部校验区 + §4.4 命名，并实际执行 `run-release.ps1 -ListOnly` 确认 0 违例
5. **发布门槛（一票否决）**：`01 §4.1/§4.3`「真源状态」列存在任何 `待刷新` 即打回，不得进入发布执行

## 3. 「真源状态」列口径（`01 §4.1/§4.3` 表新增末列）

| 取值 | 含义 | 填写规则 |
|---|---|---|
| `-` | 非真源驱动脚本 | 手写 / 编辑型脚本固定填 `-` |
| `已同步` | 真源驱动且脚本与当前真源一致 | 首次生成完成、或强制刷新完成后 |
| `待刷新` | 真源已变更但脚本未重生成 | 仅 >50 KB 挂起期间出现；发布前必须清零 |

## 4. 阈值说明

- ≤50 KB：重生成成本低，随变更同步可降低发布前集中刷新的遗忘风险
- \>50 KB：整文件重读 + 重写的 token 与出错成本显著上升，改为挂起 + 发布前统一刷新
- 与 §4.3 归并追加上限（50 KB）共用同一阈值，无需记两套数字
