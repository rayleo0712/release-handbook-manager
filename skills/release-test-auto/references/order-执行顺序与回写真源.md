# 执行顺序与回写真源（rta 分片）

> 本分片由 `skills/release-test-auto/SKILL.md` §六 执行顺序搬迁而来，16 步顺序（含两类型门控）、修改回写 `rhm` 真源强制表、回写 4 条规则、验证方式。
> 加载时机：正式开跑前确认步骤顺序、测试过程中改动了 `rhm` 材料、测试完成后回填 05 / 05-1 / 01。

## 六、执行顺序

本 Skill 执行时，应按以下顺序：

1. 读取 `release/version.json`
2. 读取当前版本 `05-1`
3. 补齐账号信息（当前版本优先，上一个版本兜底；含「节点/角色 → 测试账号」映射）
4. 检查启动命令是否存在
5. 生成或更新启动脚本
6. 生成或更新恢复脚本
7. 生成或更新恢复后校验脚本
8. 在 IDE 内置终端或等价命令行环境中启动测试环境
9. 恢复数据库基线
10. 执行恢复后校验
11. 生成或更新两阶段测试执行脚本（quick / render，见 `gen-生成内容清单.md` §3.4）
12. 执行类型一·快速测试（curl/API 层，正向 + 逆向全量用例，按节点/角色账号 token 发请求，断言后端真实状态）
13. **门控判断**（`coverage-测试覆盖规则.md` §5.2）：quick 存在失败 → 停止，修复后重跑 quick，**不得进入渲染**；quick 全过或用户明确指令 → 执行类型二·渲染测试（Playwright 全量用例，对应账号登录页面 1:1 真实操作）
14. 持续写入结果文件（`run-status.json` 含 `stage` 标注）
15. 生成最终测试报告（分阶段统计；渲染未执行须注明原因）
16. 回填当前版本发布材料
    - `05-发布后验证记录.md`：回填技术执行结果、恢复校验、失败日志、脚本输出
    - `05-1-功能验收用例(非技术版).md`：回填用户可见结果、通过/不通过、截图路径、备注
    - `01-更新手册.md` 或 `05`：登记结构化结果文件、截图、日志路径，保证可追溯

## 关键约束 · 修改回写 `rhm` 真源（强制）

若在自动化测试执行过程中，因发现缺陷、适配环境问题、调整测试策略等原因，对 `rhm` 生成的任何内容进行了修改，**必须立即将修改内容同步写回 `rhm` 对应的原始文件中**，确保 `rhm` 作为发布材料唯一真源的权威性和一致性。

具体包括（但不限于）：

| 修改类型 | 必须回写的 `rhm` 文件 | 回写内容示例 |
|---------|---------------------|------------|
| SQL 脚本调整 | `02-db-NNN.sql`、`03-config-NNN.sql` | 新增的校验语句、修复的字段类型、调整的执行顺序 |
| 配置变更 | `03-config-NNN.sql`、`01-更新手册.md` §3.x | 菜单调整、权限变更、角色配置、字典参数修改 |
| 发布步骤调整 | `01-更新手册.md` §4、§5、§6 | 新增/调整的执行步骤、回滚方案变更、人工操作补充 |
| 验证标准调整 | `05-发布后验证记录.md`、`04-发布检查清单.md` | 新增的验证项、调整的预期结果、发现的边界情况 |
| 测试数据修复 | `02-db-NNN.sql`（数据修复类） | 测试过程中发现的脏数据修复、基线数据调整 |

回写规则：

1. **即时性**：修改一经确认，应立即回写，不得延迟到测试全部结束后再统一处理
2. **完整性**：不仅回写最终修改内容，还应在 `01-更新手册.md` 的 `本轮调整摘要` 中记录调整原因
3. **可追溯**：若修改涉及 `01` 中变更台账的 `当前有效摘要` 调整，应同步更新关联的 `05-1` 测试用例
4. **禁止行为**：禁止仅在 `rta` 的测试输出目录（`test-output/`）或临时脚本中保留修改，而不回写到 `rhm` 的原始真源文件
5. **执行顺序调整硬约束**：rta 若发现需要调整 SQL 先后顺序（如外键/数据依赖导致的顺序错误），禁止只在注释里说明或只调换临时执行顺序；必须回写为 rhm 的文件名顺序——按 `rhm` 的 `scripts-sql-规范.md` §4.4 重命名定宽序号、补 `-- @depends` 机器声明，并在版本目录执行 `run-release.ps1 -ListOnly` 确认 0 违例后才算完成回写

验证方式：

- 测试执行结束后，应检查 `rhm` 相关文件的修改时间戳，确认关键修改已回写
- 在 `final-report.md` 中应包含一节「`rhm` 真源同步记录」，列出测试过程中对 `rhm` 文件的所有修改

补充：

- 若执行过程中发生代码修复，应在“第 8 步启动测试环境”与“第 9 步恢复数据库基线”之间插入“停止旧进程 → 重启环境 → 判断是否重置数据”的续跑流程

## 与归档口径的衔接

- 回填 05 时，历史轮次记录一律移入当前版本目录下的 `archive/`，发布执行文件（01–06）保持单层平铺
- 发布执行阶段不得读取 `archive/`；仅在做「05 瘦身 / 历史轮次归档」时才允许访问
