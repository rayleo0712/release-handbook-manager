# 测试覆盖规则（rta 分片）

> 本分片由 `skills/release-test-auto/SKILL.md` §1.2.1 逆向场景补齐辅助真源、§四 测试覆盖规则搬迁而来，原文口径不变。
> 加载时机：判断逆向场景是否可自动补齐、设计正向/逆向用例、核对覆盖是否充足时。

## 1.2.1 逆向场景补齐辅助真源

当 `05-1` 中逆向场景不足、需要由 AI 自动补齐时，可读取以下辅助真源：

- 当前版本 `01-更新手册.md`
- 当前版本 `04-发布检查清单.md`
- 项目中的菜单 / 路由 / 权限配置
- 项目中的接口文档、状态流转说明、角色权限说明

约束：

1. 只有在上述辅助真源至少存在一类、且足以支撑页面 / 状态 / 权限判断时，才允许自动补齐逆向场景
2. 若缺少这些辅助真源，本 Skill 应明确提示“逆向测试真源不足”，不得凭空脑补逆向场景
3. 自动补齐的逆向场景必须在结果报告中单独标记为“AI 自动补充逆向场景”
4. 自动补齐的逆向场景必须生成稳定的 `case_id`，并纳入 `test-output/case-results/*`、`total_count`、`completed_count`、`checkpoints.json` 与最终报告统计；不得只在文字说明中提及而不进入统一计数

## 四、测试覆盖规则

自动化测试**不得只覆盖正向场景**。

### 4.1 正向场景

- 主流程可顺利执行
- 多角色审批链可走通
- 列表查询、分页、详情展示正常

### 4.2 逆向场景

至少补齐以下三类：

1. **权限逆向**
   - 无权限账号访问页面
   - 无权限账号直接打开 URL
   - 非当前审批人尝试审批

2. **状态逆向**
   - 非法状态下重复提交
   - 已终止对象尝试恢复
   - 已处理记录再次操作

3. **输入逆向**
   - 必填项为空
   - 超长输入
   - 非法格式
   - 边界值输入

### 4.3 规则

- 若 `05-1` 已明确写出逆向场景，则严格按 `05-1` 执行
- 若 `05-1` 主要只有正向场景，且 `01` / `04` / 菜单路由权限配置 / 接口文档等辅助真源充足，本 Skill 才可基于页面、状态、权限补齐必要逆向测试
- 若辅助真源不足，应明确提示“逆向测试真源不足”，不得凭空补齐
- 自动补齐的逆向测试必须在结果报告中单独标明“AI 自动补充逆向场景”
