# 发布自动化测试执行

本 Skill 负责“自动化测试执行”：把发布/UAT 测试从人工点击升级为可由 IDE 终端或命令行独立运行、可恢复、可落盘的自动化流程。**细则全在 `references/`，按文末索引表加载，严禁全读一遍。**

- 边界：`rhm` 负责发布材料真源、`05-1` 验收用例、账号准备、SQL/检查清单/日志等治理内容；`rta` 读取这些真源，自动生成测试脚本并实际执行测试
- 别名：`rta` = `release-test-auto`，聊天中提到 `rta` 即按本 Skill 处理

## 何时使用

出现以下意图即启用本 Skill：

- 要求 AI 模拟人工进行 UAT / 回归测试
- 要求基于 `05-1-功能验收用例(非技术版).md` 执行自动化测试
- 要求恢复数据库备份后再跑测试
- 要求 IDE 终端或命令行自动启动项目、修 bug 后重启续跑
- 要求生成自动化测试脚本、恢复脚本、恢复后校验脚本、测试结果报告

## 核心目标

目标不是“在对话里手工点完测试”，而是建立一条可独立运行的自动化测试链路：① 读取当前版本发布真源 → ② 读取 `05-1` 的账号与验收场景 → ③ 自动启动测试环境 → ④ 自动恢复数据库基线 → ⑤ 自动校验恢复结果 → ⑥ 自动执行正向 + 逆向测试 → ⑦ 持续落盘进度与结果 → ⑧ 会话中断也可续跑到完成

## 一、输入真源

- **1.1 版本真源**：`release/version.json`，读取 `version`、`previousVersion`、当前版本目录路径
- **1.2 验收真源**：`release/versions/{version}/05-1-功能验收用例(非技术版).md`，账号读取规则见下
- **1.2.1 逆向补齐辅助真源** → `coverage-测试覆盖规则.md`
- **1.3 环境启动真源**、**1.5 数据基线真源** → `env-环境准备与启动.md`
- **1.4 结果文件真源**：必须持续写入磁盘，至少含 `test-output/run-status.json`、`checkpoints.json`、`case-results/{case-id}.json`、`final-report.md`；推荐字段 → `resume-长时运行与中断恢复.md`

账号读取规则：

1. **优先读取当前版本 `05-1` 的 `## 2. 角色准备`**
2. 某角色缺 `测试账号` / `测试密码` 时，才允许读取上一个版本同名 `05-1`
3. 上一版路径固定为 `release/versions/{previousVersion}/05-1-功能验收用例(非技术版).md`
4. 禁止继续向更早历史版本追溯
5. `previousVersion` 为空、缺失、不存在或当前已是首个版本，则不得再尝试历史迁移；此时只允许使用当前版 `05-1` 已填写的账号信息与默认密码规则
6. 进入**自动化执行模式**后，所需角色仍无法解析出 `测试账号`，必须中止执行并明确列出缺失角色；密码允许按默认规则补足，但账号不能为空

## 二~六、章节索引

- **二 工作模式**：**脚本生成模式**只出骨架/TODO，须标记“已生成但仍不可执行”；**自动化执行模式**真跑 UAT/回归，须先满足 6 项最小条件 → `env-环境准备与启动.md`（**执行前强制加载**）
- **三 生成内容** → `gen-生成内容清单.md`（6 类脚本与结果文件的命名与职责）+ `shell-编码与执行踩坑.md`（中文显示编码、PowerShell 管道导入 SQL 的禁止与推荐做法）
- **四 覆盖规则** → `coverage-测试覆盖规则.md`：正向 + 三类逆向（权限/状态/输入）；**两类型门控**：默认 curl 快测全量，全过或明确指令才跑 Playwright 渲染；流程引擎禁 SQL 直推（含夹具）
- **五 长时运行** → `resume-长时运行与中断恢复.md`：不依赖会话存活、每条用例立即落盘、断点恢复、完成判定、防卡死超时、修复后重启续跑
- **六 执行顺序** → `order-执行顺序与回写真源.md`：16 步顺序（含两类型门控）、**修改回写 `rhm` 真源强制表（5 类修改 × 回写文件）**、回写 4 条规则与验证方式

## 上下文读取纪律（硬红线）

1. **禁止整文件读写**：`release/versions/**` 下超过 30 KB 的文件，必须 `Grep` 定位小节 + `Read(offset, limit)` 精读，禁止无条件全量 `Read`
2. **大文件禁止整体覆盖**：超过 50 KB 的文档禁止 `Write` 整体重写，必须 `SearchReplace` 定点插入
3. **搜索必须限定目录**：`SearchCodebase` / `Grep` 必须带 `target_directories` 或 `glob`，禁止全仓裸搜
4. **references 按需加载**：只允许按下方索引表加载对应分片，禁止「保险起见全读一遍」
5. **发布执行阶段不得读取 `archive/`**

## 七、结果输出要求

必须至少输出：

1. 本次测试版本号
2. 执行环境与启动命令
3. 是否成功恢复数据库
4. 分阶段统计（quick / render 各自的总用例数、成功、失败、跳过；渲染未执行须注明原因）
5. 失败片段 / 失败用例清单
6. 截图与日志路径
7. 是否真正“全部完成”
8. 本次是否发生“修复后重启续跑”
9. 本次逆向场景中哪些是 `05-1` 原生提供，哪些是 AI 自动补充
10. `05` / `05-1` / `01` 是否已完成回填与归档

## 八、重要限制

- 不得连接生产库或准生产库自动恢复数据
- 不得把“环境没准备好”伪装成“测试通过”
- 不得只跑正向主流程就宣称完成自动化回归
- 不得把聊天会话存活当作测试完成保障
- 不得只输出日志而不写结构化结果文件
- 不得只生成 `test-output/*` 而不回填当前版本发布材料
- 不得忽略 `05-1` 当前版本账号真源
- 不得为了补账号信息继续扫描更早历史版本
- 不得在没有标准启动命令的前提下假装可以稳定自动化测试

## 九、推荐触发语句

以下表达应直接触发本 Skill：“请基于当前 05-1 自动跑一轮 UAT” / “恢复测试基线后执行回归测试” / “让 AI 模拟人工测试当前版本” / “修完 bug 后重启并续跑自动化测试” / “生成数据库恢复、校验和自动化测试脚本”
