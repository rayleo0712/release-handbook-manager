# release 目录说明

`release/` 用于存放版本发布资料、发布检查清单、验证记录与版本更新日志。

本目录主要服务于“准备发版”或“回看某个版本交付内容”的场景，不直接承载业务开发代码。

版本号唯一真源是 `release/version.json`，并且**只能人工维护**。日常开发、补文档、补发布材料时，AI 只能沿用当前版本号，不能自动生成或递增新版本号。

## 1. 目录结构

| 路径 | 用途 |
| :--- | :--- |
| `versions/` | 按版本号归档的发布材料 |

## 2. 版本目录约定

每个版本目录通常包含：

- `01-更新手册.md`
- `04-发布检查清单.md`
- `05-发布后验证记录.md`
- `06-版本更新日志.md`

如果后续引入 SQL、升级脚本、回滚说明，也应继续在对应版本目录内维护。

## 3. 使用建议

- 需要准备发版时，先查看最新版本目录是否已有模板可复用。
- 需要追溯某次上线内容时，优先看版本目录内的更新日志与验证记录。
- 不要把临时开发笔记直接写入本目录，发布资料应保持面向交付。
