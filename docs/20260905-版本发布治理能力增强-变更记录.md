### 模块 B：SQL 脚本强制可校验机制（功能增强）

### 模块 C：05-1 角色账号信息迁移规则（功能增强）

**问题背景**：多版本连续迭代时，测试账号密码等稳定资源每次都要重新填写；但又需要避免无限追溯更早历史版本带来不确定因素。

### 模块 D：新增配套 Skill release-test-auto / 简称 rta（新增模块）

**定位**：与 rhm 形成「真源治理 → 自动化执行 → 回填归档」的完整闭环。rhm 负责真源治理；rta 负责自动化测试执行落地。

**核心能力清单**：

| 能力项 | 说明 |
|---|---|
| 输入真源读取 | 版本真源（release/version.json）+ 验收真源（当前版本 05-1）+ 环境启动真源（IDE 终端启动命令）+ 数据库基线真源 |
| 角色账号解析 | 当前版本优先、上一个版本兜底；禁止追溯更早历史；自动化执行模式下所需角色必须全部解析到可用测试账号（密码可按默认规则补足） |
| 逆向场景补齐 | 权限逆向、状态逆向、输入逆向三类；必须基于辅助真源（01/04/菜单路由权限配置/接口文档）方可补齐；不足时明确提示真源不足 |
| 内容生成 | 启动脚本、数据恢复脚本、恢复后校验脚本、自动化测试执行脚本、结构化结果文件组 |
| 结果文件真源 | run-status.json / checkpoints.json / case-results/{case-id}.json / final-report.md；每条用例执行后立即落盘 |
| 长时间运行保障 | IDE 终端独立运行，不依赖聊天会话存活；单用例/页面等待/登录超时防卡死；断点续跑（读取 checkpoints 跳过已完成用例） |
| 修复后重启续跑 | bug 修复后停止旧进程 → 重启环境 → 判断是否需重置数据 → 断点续跑而非全量重跑 |
| 回填归档 | 结果回填 05 技术验证、05-1 用户可见结果、01 更新手册归档登记 |

**文件位置**：
