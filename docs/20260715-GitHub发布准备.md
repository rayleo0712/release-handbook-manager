# GitHub 发布准备

本文用于说明如何将 `release-handbook-manager` 作为一个独立仓库发布到 GitHub。

## 适用场景

- 当前目录已经整理为一个独立项目目录
- 希望以 `release-handbook-manager` 作为单独仓库对外发布
- 需要在发布前完成本地初始化、自检、远端创建与首发步骤

## 当前目录建议发布名

建议直接使用目录名作为仓库名：

```text
release-handbook-manager
```

这样有 3 个好处：

1. 与 Skill 正式名称一致
2. 与仓库内 `README.md`、`README.en.md`、`SKILL.md` 表述一致
3. 方便后续在文档中统一维护安装与引用路径

## 发布前本地检查

发布到 GitHub 前，建议先确认以下事项：

- `README.md` 可作为默认中文首页直接对外展示
- `README.en.md` 可作为英文入口页对外展示
- `skills/release-handbook-manager/SKILL.md` 为最终真源版本
- `templates/` 与 `examples/` 内容完整可用
- `docs/` 中已有快速开始、使用示例、设计说明、文档导航
- `LICENSE`、`CONTRIBUTING.md`、`CODE_OF_CONDUCT.md`、`SECURITY.md` 已齐备
- 不包含真实环境地址、真实账号、真实验收记录等私有信息

## 当前目录已完成事项

截至本文编写时，当前目录已经完成以下本地准备：

- 已具备完整的公开仓库基础文档
- 已具备 `.github` 协作模板
- 已初始化为独立 Git 仓库
- 已可以直接执行首次提交与远端关联

## 推荐发布流程

### 1. 初始化本地仓库

如果当前目录还不是独立仓库，需要先执行：

```bash
git init
```

如果已经初始化过，可跳过本步骤。

### 2. 创建 GitHub 远端仓库

你可以任选下面两种方式之一。

#### 方式 A：在 GitHub 网页创建

在 GitHub 新建一个空仓库：

- 仓库名：`release-handbook-manager`
- 可见性：建议按你的发布策略选择 `Public` 或 `Private`
- 初始化选项：不要勾选自动生成 `README`、`.gitignore`、`LICENSE`

创建完成后，记下仓库地址，例如：

```text
https://github.com/<你的账号或组织>/release-handbook-manager.git
```

#### 方式 B：使用 GitHub CLI 创建

如果本机已安装并登录 `gh`，可执行：

```bash
gh repo create release-handbook-manager --public --source . --remote origin --push
```

如果需要创建私有仓库，可将 `--public` 改为 `--private`。

## 首次提交与远端关联

如果你是通过网页先创建空仓库，推荐在当前目录执行：

```bash
git add .
git commit -m "chore: initialize release-handbook-manager repository"
git branch -M main
git remote add origin https://github.com/<你的账号或组织>/release-handbook-manager.git
git push -u origin main
```

## 首发后建议补充动作

仓库首次推送成功后，建议继续完成以下动作：

1. 在 GitHub 仓库设置中补充简介、标签、官网链接
2. 上传仓库封面图后，检查社交预览效果
3. 补充首个 Release，例如 `v1.0.0`
4. 在 README 中持续保持中文主站与英文入口的一致性

## 推荐仓库设置

建议在 GitHub 中补充以下仓库信息：

- Description：
  `A reusable release governance Skill for AI-assisted software delivery.`
- Topics：
  `skill`、`ai`、`release`、`release-management`、`documentation`、`workflow`
- Website：
  如后续有独立介绍页或文档站点，可在此配置

## 当前环境注意事项

如果当前命令行环境中：

- `git` 可用
- `gh` 不可用

则说明你可以完成本地 Git 初始化与提交，但不能直接通过 CLI 创建 GitHub 仓库。此时建议优先使用 GitHub 网页创建远端仓库，再回到本地执行远端关联与推送。
